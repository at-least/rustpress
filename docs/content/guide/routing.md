# Routing

## File-Based Routing

rustpress uses file-based routing: the generated HTML pages are mapped from the directory structure of the source markdown files. Every page gets a **directory-style URL** with a trailing slash, and the output is always `index.html` inside that directory. Given the following source directory:

```
.
├─ guide
│  ├─ getting-started.md
│  └─ index.md
├─ index.md
└─ prologue.md
```

The generated HTML pages will be:

```
index.md                  -->  /index.html                  (accessible as /)
prologue.md               -->  /prologue/index.html         (accessible as /prologue/)
guide/index.md            -->  /guide/index.html            (accessible as /guide/)
guide/getting-started.md  -->  /guide/getting-started/index.html
```

The resulting HTML can be hosted on any web server that can serve static files. Because every URL is a directory, no host-side rewrite rules are needed — serving `dir/index.html` for `dir/` is what every static host does by default.

## Root and Source Directory

There are two important concepts in the file structure of a rustpress project: the **project root** (the *site directory*) and the **source directory**.

### Project Root

The project root is the directory containing `rustpress.toml`. It is also where the build writes its output (`public/`) and where an optional `static/` directory lives.

When you run `rustpress build` or `rustpress serve` from the command line without arguments, the current working directory is the project root. To specify a sub-directory as root, pass its path. For example, if your site is located in `./docs`, run `rustpress serve docs`:

```
.
├─ docs                    # project root
│  ├─ rustpress.toml       # config
│  └─ content              # source dir
│     ├─ getting-started.md
│     └─ index.md
└─ ...
```

```sh
rustpress serve docs
```

### Source Directory

The source directory is where your markdown source files live. By default it is `content` inside the project root — unlike VitePress, where the two coincide. You can change it with the [`srcDir`](../reference/site-config#srcdir) config option, which is resolved relative to the project root. With `srcDir = "src"`:

```
.                          # project root
├─ rustpress.toml
└─ src                     # source dir
   ├─ getting-started.md
   └─ index.md
```

The resulting source-to-HTML mapping:

```
src/index.md            -->  /index.html            (accessible as /)
src/getting-started.md  -->  /getting-started/index.html
```

Files can be excluded from the page set with [`srcExclude`](../reference/site-config#srcexclude).

## Linking Between Pages

Relative links are resolved **at build time** against the linking page's source location and rewritten to the target page's canonical URL. Both `.md` and `.html` extensions work, and the best practice is to omit the extension:

```md
<!-- Do -->
[Getting Started](./getting-started)
[Getting Started](../guide/getting-started)

<!-- Also resolved -->
[Getting Started](./getting-started.md)
[Getting Started](./getting-started.html)
```

Links are resolved in *source space*: they name source files, and the page's final URL is what gets emitted — so a link keeps working when the target is moved by a [rewrite](#route-rewrites). Anchors (`#section`) are preserved.

A relative link that matches no page passes through untouched, and the build reports it as a dead link (see [Dead Links](#dead-links)).

Absolute links that name a page (`/guide/getting-started`, `/guide/getting-started.md`) are rewritten to that page's URL too, so the emitted link always carries the trailing slash a directory-style site needs. Absolute links to anything else are emitted as written. Either way [`base`](../reference/site-config#base) is prepended when the site is deployed under a sub-path; resolved relative links get the same prefix.

Learn more about linking to assets such as images in [Asset Handling](./asset-handling).

### Linking to Non-rustpress Pages

If you want to link to a page in your site that is not generated by rustpress, you'll either need to use the full URL (opens in a new tab) or explicitly specify the target:

**Input**

```md
[Link to pure.html](/pure.html){target="_self"}
```

**Output**

[Link to pure.html](/pure.html){target="_self"}

::: tip Note
A link with an attribute block is emitted as a raw anchor, so the link text cannot contain markdown. Alternatively, use the anchor tag syntax directly:

```md
<a href="/pure.html" target="_self">Link to pure.html</a>
```
:::

## Clean URLs

rustpress has no `cleanUrls` option because its URLs are always clean: `/guide/getting-started/` is a directory containing `index.html`. There is no `.html`-suffix mode, and links written with a `.html` suffix are rewritten to the directory form.

If you need a specific URL to end in `.html` (for example to keep an old link alive), put the file in [`static/`](./asset-handling#the-static-directory) and link to it with `{target="_self"}` as shown above.

## Route Rewrites

You can customize the mapping between the source directory structure and the generated pages with the [`rewrites`](../reference/site-config#rewrites) option. Keys are source paths relative to the source directory; values are the destination paths, in the same `.md` spelling:

```toml [rustpress.toml]
[rewrites]
"packages/pkg-a/src/index.md" = "pkg-a/index.md"
"packages/pkg-a/src/foo.md" = "pkg-a/foo.md"
"packages/pkg-b/src/index.md" = "pkg-b/index.md"
"packages/pkg-b/src/bar.md" = "pkg-b/bar.md"
```

A key may end with `:rest*` to capture everything after a prefix:

```toml [rustpress.toml]
[rewrites]
"en/:rest*" = ":rest*"
```

This is the pattern for VitePress's canonical multi-language layout, where the default language lives in `content/en/` but is served at `/` — see [Internationalization](./i18n). `:rest*` is the only pattern parameter; named segments such as `:pkg/:slug*` and function rewrites are not supported.

::: warning Relative Links with Rewrites
Relative links are resolved against the **source** paths, so a link from `packages/pkg-a/src/foo.md` to `packages/pkg-b/src/bar.md` is still written `../../pkg-b/src/bar`. The emitted URL is the rewritten one.
:::

## Dead Links

The build resolves every `href` and `src` in the rendered pages. A relative link that matches no page, or an absolute path that matches neither a page nor a file in the output directory, fails the build with a report:

```
Error: 1 dead link(s) found (ignoreDeadLinks silences this):
  /guide/routing/ → guide/does-not-exist
```

External (`http://`, `https://`, `mailto:`) targets and pure anchors are never checked. Silence the check with [`ignoreDeadLinks`](../reference/site-config#ignoredeadlinks): `true` ignores everything, a list of strings ignores links starting with any of the prefixes.

## Dynamic Routes

VitePress can generate many pages from one `[param].md` template and a JavaScript paths loader. rustpress has no JavaScript at build time and no equivalent: every page is one markdown file. See [Coming from VitePress](./coming-from-vitepress).
