# Internationalization

To use the built-in i18n features, create one content subdirectory per additional language:

```
content/
├─ es/
│  ├─ foo.md
├─ fr/
│  ├─ foo.md
├─ foo.md
```

Then declare the locales in `rustpress.toml`. The special key `root` describes the top-level content; every other key names a content subdirectory, served under a URL prefix of the same name (`content/fr/**` becomes `/fr/**`):

```toml [rustpress.toml]
# shared properties and other top-level stuff...

[locales.root]
label = "English"
lang = "en"

[locales.fr]
label = "French"
lang = "fr"  # optional, becomes the `lang` attribute on the <html> tag
```

The following properties can be set for each locale (including `root`):

| key | effect |
| --- | --- |
| `label` | display name in the language switcher (required) |
| `lang` | `<html lang>` for the locale's pages; falls back to the site-level `lang` |
| `title` | site title shown in the navbar and `<title>` of the locale's pages |
| `description` | default `<meta name="description">` for the locale's pages |

Once more than one locale is declared, the navbar gains a language flyout and the mobile menu a language list. Each entry links to the **same page** in the other locale when it exists (`/guide/foo/` ↔ `/fr/guide/foo/`), and to that locale's root otherwise.

The remaining per-locale overrides VitePress offers — `head`, `themeConfig`, `titleTemplate`, `link`, `dir` and per-locale markdown strings such as container labels — have no counterpart. Navigation, sidebar, footer texts and [container labels](./markdown#custom-containers) are configured once for the whole site.

## Separate directory for each locale

The following is a perfectly fine structure:

```
content/
├─ en/
│  ├─ foo.md
├─ es/
│  ├─ foo.md
├─ fr/
   ├─ foo.md
```

To serve the `en/` tree at the site root, map its paths with [`rewrites`](../reference/site-config#rewrites) and keep `root` as the locale for it:

```toml [rustpress.toml]
[rewrites]
"en/:rest*" = ":rest*"

[locales.root]
label = "English"
lang = "en"

[locales.es]
label = "Español"
lang = "es"

[locales.fr]
label = "Français"
lang = "fr"
```

rustpress will not redirect `/` to `/en/` or pick a language from the browser; if you want that, configure it on your server. For example, on Netlify, you can add a `static/_redirects` file like this:

```
/*  /es/:splat  302  Language=es
/*  /fr/:splat  302  Language=fr
/*  /en/:splat  302
```

## RTL Support

There is no `dir` option; right-to-left layouts are not supported.
