# Internationalization

To use the built-in i18n features, create one content subdirectory per additional language:

```
content/
├─ es/
│  ├─ foo.md
├─ fr/
│  ├─ foo.md
├─ foo.md
```

Then declare the locales in `rustpress.toml`. The special key `root` describes the top-level content; every other key names a content subdirectory, served under a URL prefix of the same name (`content/fr/**` becomes `/fr/**`):

```toml [rustpress.toml]
# shared properties and other top-level stuff...

[locales.root]
label = "English"
lang = "en"

[locales.fr]
label = "French"
lang = "fr"  # optional, becomes the `lang` attribute on the <html> tag
```

The following properties can be set for each locale (including `root`):

| key | effect |
| --- | --- |
| `label` | display name in the language switcher (required) |
| `lang` | `<html lang>` for the locale's pages; falls back to the site-level `lang` |
| `title` | site title shown in the navbar and `<title>` of the locale's pages |
| `description` | default `<meta name="description">` for the locale's pages |

Once more than one locale is declared, the navbar gains a language flyout and the mobile menu a language accordion. Both are titled with the current page's language and list the other locales in the order they are declared in `rustpress.toml`. Each entry links to the **same page** in the other locale when it exists (`/guide/foo/` ↔ `/fr/guide/foo/`), and to that locale's root otherwise; the links carry `hreflang` and `rel="alternate"`. A page whose own locale is not declared (top-level content without `[locales.root]`) shows no switcher.

With [local search](../reference/default-theme-search) on, every locale gets its own index: a page searches only the pages of its own locale.

### Locale theme settings

Theme settings — navigation, UI labels, footer, edit link, outline label and so on — can be set per locale under `themeConfig`, with the same keys as at the top level of `rustpress.toml`:

```toml [rustpress.toml]
[locales.zh]
label = "简体中文"
lang = "zh-Hans"

[locales.zh.themeConfig]
returnToTopLabel = "回到顶部"
darkModeSwitchLabel = "主题"
lastUpdatedText = "最后更新于"

[locales.zh.themeConfig.outline]
label = "页面导航"

[locales.zh.themeConfig.docFooter]
prev = "上一页"
next = "下一页"

[[locales.zh.themeConfig.nav]]
text = "指南"
link = "/zh/guide/"
activeMatch = "/zh/guide/"
```

A locale's settings are layered over the site's, like VitePress does: tables merge key by key (above, `outline.level` still comes from the site's `[outline]`), anything else — a string, an array such as `nav` — replaces the site's value, and keys the locale does not set keep the site's.

The keys a locale can set: `nav`, `logo`, `siteTitle`, `socialLinks`, `askAiUrl`, `outline`, `aside`, `editLink`, `lastUpdatedText`, `docFooter`, `footer`, `notFound`, `gradedContainers`, `returnToTopLabel`, `sidebarMenuLabel`, `darkModeSwitchLabel`, `lightModeSwitchTitle`, `darkModeSwitchTitle`, `langMenuLabel`, `navMenuLabel`, `mobileMenuLabel` and `skipToContentLabel`. Any other key fails the build. Per-locale sidebars are path-keyed instead (`[sidebar."/zh/guide/"]`, see [Sidebar](../reference/default-theme-sidebar)), and the [search](../reference/default-theme-search) strings are site-wide.

The remaining per-locale overrides VitePress offers — `head`, `titleTemplate`, `link`, `dir` and per-locale markdown strings such as container labels — have no counterpart.

## Separate directory for each locale

The following is a perfectly fine structure:

```
content/
├─ en/
│  ├─ foo.md
├─ es/
│  ├─ foo.md
├─ fr/
   ├─ foo.md
```

To serve the `en/` tree at the site root, map its paths with [`rewrites`](../reference/site-config#rewrites) and keep `root` as the locale for it:

```toml [rustpress.toml]
[rewrites]
"en/:rest*" = ":rest*"

[locales.root]
label = "English"
lang = "en"

[locales.es]
label = "Español"
lang = "es"

[locales.fr]
label = "Français"
lang = "fr"
```

rustpress will not redirect `/` to `/en/` or pick a language from the browser; if you want that, configure it on your server. For example, on Netlify, you can add a `static/_redirects` file like this:

```
/*  /es/:splat  302  Language=es
/*  /fr/:splat  302  Language=fr
/*  /en/:splat  302
```

## RTL Support

There is no `dir` option; right-to-left layouts are not supported.
